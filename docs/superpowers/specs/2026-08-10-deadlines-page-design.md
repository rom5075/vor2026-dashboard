# VOR 2026: отдельная страница дедлайнов

**Дата спецификации:** 10.08.2026
**Источник дат и пометок:** `VOR2026_DEADLINES_MATRIX.md`, составлена 10.08.2026

## Цель

Добавить к опубликованному дашборду отдельную страницу, на которой за один взгляд видно, когда сдаётся каждая из пяти доработок по трём версиям плана:

1. оперативный план команды;
2. план v14 для руководства IBS;
3. клиентский план SST.

На странице показываются только финальные даты выхода на Prod. Даты UAT и окна исправления ошибок в эту страницу не входят.

## Объём изменений

- создать самостоятельную страницу `deadlines.html`;
- добавить в шапку основного дашборда ссылку «Дедлайны»;
- добавить на странице дедлайнов ссылку «Назад к карте работ»;
- включить `deadlines.html` в сборку GitHub Pages;
- включить страницу в офлайн-кэш PWA и не допустить подмены главной страницы закэшированной страницей дедлайнов;
- кратко описать новую страницу в `README.md` и актуализировать `HANDOFF.md`;
- сохранить `VOR2026_DEADLINES_MATRIX.md` в репозитории как проверяемый источник цифр.

Изменение не пересчитывает задачи, зависимости, сроки или загрузку сотрудников в основном дашборде.

## Оговорки и предупреждения

Над таблицей размещается заметное предупреждение: Д1 — единственная доработка, у которой оперативная дата превышает обязательство перед заказчиком.

Для Д2 и Д3 сохраняется отдельная оговорка из матрицы: оперативный план не учитывает уход Java-разработчика; фактические даты могут сдвинуться вправо и считаются устаревшими до пересчёта. Эта оговорка не изменяет отображаемые числа.

Под таблицей указывается:

- все даты — финиш задачи Deployment on Prod в MS Project;
- дата составления матрицы — 10.08.2026;
- назначение трёх версий: команда, руководство IBS, клиент SST.

## Визуальное решение

Страница продолжает визуальный язык существующего дашборда: те же цветовые переменные блоков, светлая и тёмная темы, скругления, размерный ритм и системный шрифт Segoe UI/Arial. Отдельная визуальная подпись страницы — крупные, выровненные табличные даты; цвет используется только для смысла риска, а не для украшения.

На широком экране используется одна таблица с четырьмя основными колонками:

`Доработка | Оперативный план | Руководству v14 | Клиент SST`

Пометки отклонений располагаются вторым уровнем под соответствующими датами v14 и клиента. Оперативная дата выделяется как фактический текущий прогноз.

На экранах до 640 px каждая строка превращается в компактную карточку с теми же четырьмя полями. Горизонтальная прокрутка для чтения основных дат не требуется.

Цветовые статусы сопровождаются текстом и символом, поэтому смысл не зависит только от цвета. Интерактивные ссылки имеют заметный `focus-visible`. Учитывается `prefers-reduced-motion`; обязательной анимации нет.

## Архитектура и данные

`deadlines.html` — статический автономный документ. Все даты и пометки записываются в семантическую HTML-таблицу непосредственно из утверждённой Markdown-матрицы. Runtime-парсер Markdown и общий JavaScript-файл с основным монолитным дашбордом не создаются.

JavaScript на новой странице отвечает только за переключение темы и регистрацию существующего service worker. Выбранная тема использует тот же ключ `localStorage`, что и основной дашборд.

GitHub Actions копирует `deadlines.html` в `_site/deadlines.html`. Service worker кэширует обе страницы по их собственным URL; сетевой ответ `deadlines.html` не должен записываться под ключ главной страницы `./`.

## Обработка отказов

- без JavaScript таблица и все даты остаются видимыми;
- при недоступности `localStorage` страница остаётся в светлой теме;
- при отсутствии сети ранее посещённая страница дедлайнов открывается из PWA-кэша;
- если GitHub Pages не находит `deadlines.html`, проверка деплоя считается неуспешной.

## Проверка и критерии приёмки

1. Все 15 дат Prod дословно совпадают со сводной таблицей `VOR2026_DEADLINES_MATRIX.md`.
2. Все десять цветовых пометок отклонений совпадают с разделом «Запас и просрочка» матрицы.
3. Оговорка об устаревших оперативных датах Д2 и Д3 присутствует и не скрыта на мобильном экране.
4. Д1 явно отмечена как превышающая клиентский срок на 14 дней.
5. Строки идут в порядке Д4, Д5, Д2, Д1, Д3.
6. Ссылки между основной страницей и `deadlines.html` работают с клавиатуры и мыши.
7. Таблица читается в светлой и тёмной темах на широком экране и на ширине iPhone.
8. Главная страница сохраняет существующие вкладки, PWA-функции и данные без изменений.
9. Локальные HTML-проверки проходят без ошибок; визуальная проверка выполняется снимками desktop и mobile.
10. После публикации GitHub Actions завершается успешно, а публичные URL `/` и `/deadlines.html` отвечают и показывают соответствующие страницы.

## Вне объёма

- пересчёт планов после ухода Java-разработчика;
- изменение данных существующего гантта;
- вывод UAT, UAT bug fixes или полных окон работ;
- автоматический импорт XML/MS Project;
- фильтры, сортировка пользователем и редактирование дат через интерфейс.
